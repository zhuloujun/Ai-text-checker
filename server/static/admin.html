管理员登录

输入你在 GitHub 仓库 Secrets 里设置的 HF_ADMIN_TOKEN（即服务的管理员密码 ADMIN_TOKEN）。密码只保存在这个页面的内存里，刷新后需重新输入。

签发 API Key

Key 自带签名，服务重启后仍然有效；Key 只在这里显示一次，请立即保存。
改动 ADMIN_TOKEN（或 KEY_SECRET）会让之前签发的所有 Key 失效。

用量与作废

用量只记在内存里，服务重启后清零。作废会立即生效；要在重启后仍然有效，请在 GitHub 仓库 Settings → Secrets and variables → Actions 的 Variables 里把 Key 编号加入 REVOKED_KEY_IDS（多个用英文逗号分隔），然后重新部署。

校准

最简单的做法（推荐）：先在首页检测几篇你确定来源的文章，在每段下方点“这段是 AI / 这段是人写”，然后回到这里点下面的按钮。 系统会把你的标注按文体（现代汉语 / 文言 / 诗词 / 英文）分别与内置公开数据合并校准，并永久保存（服务重启后仍然有效）。标注越多、AI 和人写两类都有，效果越好。

手动校准（进阶）：

开源检测方法的默认阈值不是按中文学术文字定的。校准能让结果适合你的文字风格：左边放确定是你自己写的文字（最好是 2022 年以前、没用过 AI 的旧稿，含引文较多的也放进来），右边放AI 生成的同类文字（例如让几个不同的 AI 就相同题目写的段落）。
多篇文字之间用单独一行 === 分隔，也可以直接选择多个 .txt / .docx 文件追加进来。每边建议 1 万字以上；每边达到 30 段以上时，会同时学习 LRR、GLTR 名次、预测熵、困惑度波动、句式统计等扩展特征的权重，通常更准。校准会在后台运行，可能需要几分钟到十几分钟。

现代汉语、文言、诗词、英文四种文体分别校准、互不影响：比如只用文言样本校准，只会更新文言部分的参数。选“自动”时按样本里字数最多的文体确定，其他文体的段落不参与这次校准。
